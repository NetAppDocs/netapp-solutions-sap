= SnapCenter operations
:hardbreaks:
:nofooter:
:icons: font

[.lead]
This chapter summarizes the backup, restore and recovery, SAP system refresh and asynchronous replication operations with SnapCenter.

== Backup operations

Backup operations are executed in the same way as described in https://docs.netapp.com/us-en/netapp-solutions-sap/backup/hana-sc-generic-backup-operations.html[Learn about backup operations for SAP HANA Snapshot in SnapCenter].

NOTE: If no consistency group is configured for the storage unit, SnapCenter creates a consistency group and a child consistency group with the first Snapshot backup operation. The HANA data storage is then assigned to the child consistency group. SnapCenter Snapshot backups are listed within the child consistency group.

image:hana-sc-bare-metal-asar2-image-007.png[width=601,height=191]

image:hana-sc-bare-metal-asar2-image-008.png[width=601,height=205]

== Restore and recovery

Restore and recovery operations are executed in the same way as described https://docs.netapp.com/us-en/netapp-solutions-sap/backup/hana-sc-generic-restore.html[Restore and recover SAP HANA databases with SnapCenter].

== Asynchronous storage replication

For the HANA data volume, an asynchronous storage replication has been configured.

image:hana-sc-bare-metal-asar2-image-009.png[width=601,height=180]

The replication has been configured with the MirrorAndVault policy.

image:hana-sc-bare-metal-asar2-image-010.png[width=601,height=206]

The MirrorAndVault policy includes different SnapMirror labels and retentions.

image:hana-sc-bare-metal-asar2-image-011.png[width=601,height=235]

In SnapCenter a policy has been configured to match the SnapMirror label "daily" of the ONTAP MirrorAndVault policy.

image:hana-sc-bare-metal-asar2-image-012.png[width=378,height=354]

When using the ONTAP MirrorAndVault policy, SnapCenter shows separated Vault and Mirror copies, even though the Snapshot backups are only available once at the target storage.

image:hana-sc-bare-metal-asar2-image-013.png[width=601,height=294]

== SAP system refresh

More detailed information on SAP system refresh and cloning operations using SnapCenter can be found at https://docs.netapp.com/us-en/netapp-solutions-sap/lifecycle/sc-copy-clone-introduction.html[Automating SAP HANA System Copy and Clone Operations with SnapCenter].

=== SnapCenter workflow

Operation details and pre-requisites are described in https://docs.netapp.com/us-en/netapp-solutions-sap/lifecycle/sc-copy-clone-hana-sys-refresh-with-sc.html#prerequisites-and-limitations[SAP HANA system refresh with SnapCenter]. Specifically, the target system must be added to SnapCenter before you can execute the first refresh/cloning operation.

With the first step in the cloning workflow the target host and target SID must be provided.

image:hana-sc-bare-metal-asar2-image-014.png[width=333,height=313]

Protocol selection must be "FCP".

image:hana-sc-bare-metal-asar2-image-015.png[width=334,height=312]

Optionally you can add the sc-system-refresh.sh script to automate the recovery operation.

image:hana-sc-bare-metal-asar2-image-016.png[width=352,height=331]

The below screenshot shows the job log of the cloning workflow.
